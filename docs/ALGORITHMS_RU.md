# Как разобраться в проекте

Начни с `src/app/Main.java`: это маленький пример с конкретными дорогами.
Запуск: `make run`. После этого читай алгоритмы в порядке ниже.

## 1. Граф

Вершина — район города. Ребро — дорога с весом. Вершины начинаются с 0.
`new Graph(5, false)` создаёт неориентированный граф на 5 вершинах.
`addEdge(0, 2, 7)` добавляет дорогу между районами 0 и 2 стоимостью 7.
`neighbors(v)` возвращает дороги из вершины v, `edges()` — исходные рёбра.
Для неориентированной дороги список соседей хранит оба направления.

## 2. DSU: кто с кем уже соединён

`parent[x]` — родитель вершины в дереве множества, `size[root]` — размер множества.
Изначально каждый элемент является своим родителем.

`find(x)` поднимается до корня, затем меняет родителей всех пройденных элементов
на этот корень. Следующий поиск проходит быстрее. Это path compression.

`union(a, b)` находит два корня. Если они одинаковые, объединять нечего: вернётся
`false`. Иначе меньшее дерево присоединяется к большему, число компонент уменьшается.
Так деревья остаются низкими. Это union by size.

## 3. Краскал: выбираем дешёвые дороги

1. Сортируем все дороги по цене.
2. Берём очередную дорогу и вызываем `union(from, to)`.
3. Если объединение удалось, дорога соединяет разные компоненты: включаем её.
4. Если не удалось, дорога создаёт цикл: пропускаем её.
5. Для связного графа останавливаемся после V-1 выбранных дорог.

В примере Main выбираются веса 1, 2, 3, 5: итоговая стоимость 11.
Жадный выбор корректен по свойству разреза: самое дешёвое подходящее ребро
между компонентами безопасно включать в некоторое MST.

## 4. Прим: расширяем сеть из одного района

Начинаем с вершины. Добавляем её дороги в очередь с приоритетом по весу.
Достаём самую дешёвую дорогу. Если её конец уже посещён — пропускаем.
Иначе добавляем дорогу в дерево, отмечаем новую вершину и добавляем её дороги.
Когда очередь опустеет, переходим к следующей непосещённой вершине.
Несколько стартов означают несвязный граф и дают минимальный остовный лес.
На каждом шаге выбирается минимальное ребро через разрез посещённых вершин.

## 5. Топологическая сортировка Кана

`indegree[v]` хранит число входящих рёбер. Сначала кладём в обычную очередь все
вершины без входящих рёбер. Извлекаем вершину, добавляем в ответ и уменьшаем
входящую степень её соседей. Когда степень стала нулевой, сосед готов к обработке.
Если обработали меньше V вершин, оставшиеся зависимости содержат цикл.
В DAG всегда существует вершина без входящих рёбер, поэтому процесс может продолжаться.

## 6. SCC алгоритмом Косарайю

SCC — группа вершин, где из любой вершины можно попасть в любую другую по направлениям.
Первый DFS записывает вершину в `finish`, когда все её соседи уже обработаны.
Создаём граф с обратными рёбрами. Обходим вершины в обратном порядке `finish`.
Каждый новый DFS в обратном графе собирает одну SCC.
Порядок завершения позволяет начать с компоненты, из которой в обратном графе
нельзя попасть в другую ещё не выделенную компоненту.
`nextEdge[v]` заменяет позицию цикла в рекурсивном DFS: какой сосед следующий.

## 7. Дейкстра: кратчайшие маршруты от источника

У источника расстояние 0, у остальных бесконечность. В очереди лежат пары
«вершина, известное расстояние». Достаём минимальную пару. Если она устарела,
пропускаем. Иначе для каждой исходящей дороги считаем `distance[v] + weight`.
Если стало лучше, обновляем расстояние, предшественника и добавляем новую пару.
При неотрицательных весах извлечённое актуальное минимальное расстояние уже нельзя
улучшить путём через более далёкую вершину: в этом причина корректности алгоритма.

Восстановление пути идёт назад по `previous[]`, после чего список переворачивается.
Если вершина недостижима, путь пустой. В Main путь из 0 в 4: `[0, 2, 1, 3, 4]`,
расстояние 11. Вершина 5 недостижима.

## Что стоит уметь объяснить на защите

- Почему MST не является деревом кратчайших путей от заданной вершины.
- Зачем нужны обе оптимизации DSU и почему `union` возвращает boolean.
- Почему при равных весах разные MST могут иметь одинаковую сумму.
- Почему SCC и обычная связная компонента — разные понятия.
- Почему цикл мешает топологическому порядку.
- Почему отрицательный вес разрушает жадное обоснование Дейкстры.
- Почему списки соседей занимают O(V+E), а не O(V²).
- Почему пять замеров дают разные времена, но одинаковые счётчики операций.

Измени один вес в Main, предскажи результат и запусти пример. Затем запусти
`make test`: проверки помогут увидеть, какие свойства обязаны сохраняться.
